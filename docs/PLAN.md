# План: драйвер ATI Rage Mobility M1 (8 МБ) для Windows 98

## Цель

Direct3D быстрее штатного драйвера ATI, в первую очередь в оригинальной GTA3
(запускается после правки байтов в exe, FPS сейчас низкий).

Всё, что на FPS в GTA3 не влияет (ускорение 2D, видеооверлей, TV-выход,
управление питанием), в план не входит.

## Железо

| | Sony PCG-Z505LE | Sony PCG-C1VPK |
|---|---|---|
| Роль | основная машина разработки | второй этап |
| Процессор | Pentium III 650 | Transmeta Crusoe |
| Панель | 1024×768 | 1024×480 |
| Отладочный COM | только через порт-репликатор | нет |

- Чип: семейство mach64 (Rage Pro с LCD-частью). В `atyfb` это
  `3D RAGE Mobility P/M`, PCI ID `1002:4C4D` (AGP) или `1002:4C52` (PCI).
  Точный ID на обоих ноутбуках надо снять на этапе 1.
- Хост: MacBook Pro 13" 2015 под Windows x64, сеть через USB-Ethernet,
  Claude Code запускается на нём.
- Система на ноутбуках: Windows 98 из win98-quickinstall.

## Что известно о 3D-части чипа (по исходникам Mesa)

- Аппаратной трансформации и освещения нет, чип принимает готовые экранные
  вершины и сам делает подготовку треугольника.
- Два текстурных блока, текстуры в форматах 1555, 565, 4444, 8888.
- Текстуры могут лежать в видеопамяти или в памяти AGP.
- Команды подаются записью в регистры либо пакетами через bus-master DMA.

Эти пункты взяты из `reference/mesa-7.11-mach64` и `reference/mach64-drm`
и на наших ноутбуках ещё не проверены.

## Состав драйвера

| Файл | Что это | Основа |
|---|---|---|
| `atim1.drv` | 16-битный драйвер дисплея поверх DIB engine, 2D без ускорения | `reference/vmdisp9x` |
| `atim1.vxd` | mini-VDD: доступ к регистрам, прерывание, память под DMA, AGP | `reference/vmdisp9x` |
| `atim1dd.dll` | 32-битный HAL DirectDraw и Direct3D | каркас из `reference/vmhal9x`, аппаратная часть своя |
| `atim1.inf` | установка | — |

Сборка: Open Watcom на макбуке, без среды разработки на ноутбуках.

Режимы на первом этапе ставит видео-BIOS (VBE). Это снимает самый опасный
кусок работы: тайминги LCD и растяжение, особенно для панели 1024×480.

## Этапы

### 0. Справочные материалы (сделано)

Каталог `reference/`, описание в `reference/README.md`.

### 1. Стенд

Описание и команды — в [STAND.md](STAND.md).

Сделано, проверено под wine, на Windows 98 ещё не запускалось:

1. Агент `stand/agent`: файлы, запуск программ, снимки экрана, перезагрузка.
2. Автооткат: снимок реестра в DOS и возврат, если пробная загрузка не
   подтверждена.
3. Таймер «мёртвой руки» с жёстким сбросом.
4. Утилита хоста `tools/w98.py`.

Осталось:

5. Первый запуск на Z505LE и C1VPK, проверка отката и жёсткого сброса.
6. Образ QuickInstall с уже установленным агентом и автологоном.
7. Камера макбука направлена на экраны ноутбуков.
8. Снять с ноутбуков файлы штатного драйвера и PCI ID в
   `reference/proprietary/`.

Готово, когда сборка с хоста ставится и откатывается без рук.

### 2. Замер на штатном драйвере

1. Фиксированная сцена в GTA3 (одно сохранение, одна точка, одно время суток),
   счётчик кадров.
2. FPS при 640×480 и ниже, 16 бит.
3. Профиль по времени: игра, прослойка D3D8, драйвер ATI.
4. Какой уровень интерфейса драйвера (DDI) показывает штатный драйвер в
   `dxdiag` и какие возможности он объявляет.
5. Журнал вызовов D3D от GTA3: какие состояния, форматы текстур и размеры
   пакетов игра реально использует.

### 3. Решение

- Заметная доля кадра уходит в драйвер — идём дальше.
- FPS растёт с падением разрешения и драйвер почти не виден — упираемся в
  закраску чипа; драйвер даст мало.
- Тормозит игра или прослойка D3D8 — выгоднее править рендер на стороне игры
  (`re-GTA`, `librw`), драйвер не поможет.

### 4. Минимальный драйвер

1. `atim1.drv` + `atim1.vxd` + INF: рабочий стол на Z505LE в 640×480 и
   1024×768, 16 бит, режимы через VBE.
2. DOS-окна и полноэкранный DOS не ломают систему.

### 5. DirectDraw

1. Поверхности в видеопамяти, переключение буферов, блокировка.
2. Распределитель видеопамяти под передний и задний буфер, Z и текстуры.
3. Проверка: `dxdiag`, тесты DirectDraw из DirectX SDK.

### 6. Direct3D, корректность

1. Инициализация 3D-части чипа, запись вершин через регистры.
2. Разбор командного буфера DrawPrimitives2, состояния, одна текстура.
3. Z-буфер, смешивание, туман, вторая текстура.
4. Уровень DDI — тот же, что у штатного драйвера (этап 2.4), иначе GTA3 может
   пойти по другому пути.
5. Проверка: тесты D3D из SDK, затем GTA3 доходит до игры без артефактов.

### 7. Оптимизация под GTA3

1. Подача вершин через bus-master DMA вместо записи в регистры.
2. Кэш текстур: что держать в 8 МБ, что в AGP, как вытеснять.
3. Быстрые пути под состояния из журнала этапа 2.5, отсечение лишних
   переключений состояний.
4. Замер после каждого шага на сцене из этапа 2.

Готово, когда FPS на сцене стабильно выше штатного.

### 8. Перенос на C1VPK

1. Режим 1024×480 через VBE; если BIOS его не даёт, программируем LCD-часть
   по `reference/linux-atyfb` и `reference/xf86-video-mach64-6.9.5`.
2. Те же замеры; на Crusoe узким местом может оказаться процессор.

## Риски

- **Узкое место не в драйвере.** Проверяется на этапе 2, до написания кода.
- **Жёсткие зависания при отладке 3D и DMA.** Без COM-порта остаются только
  «хлебные крошки» на диске и кнопка питания.
- **GTA3 требует 16 МБ.** На 8 МБ запас под текстуры мал, без AGP-текстур
  выигрыш может съесть подкачка текстур.
- **Лицензии.** `atyfb` под GPL: только читаем, код не переносим. Mesa, DRM,
  драйвер X.org и vmdisp9x/vmhal9x под MIT, их код можно использовать.

## Уточнено

- На Z505LE есть гнездо RJ-45 и порт-репликатор с COM-портом.
- Фикс в `gta3.exe` отключает проверку, что у видеокарты не меньше 12 МБ.
  Значит, игра рассчитывает на больший объём: распределение 8 МБ и
  AGP-текстуры (этап 7.2) становятся одним из главных пунктов.
- На ноутбуках стоит последний DirectX для Windows 98 (9.0c). GTA3 работает
  через интерфейс D3D8 этой версии.

## Нужно докупить

- Адаптер USB–RS232 для макбука и нуль-модемный кабель DB9 (мама–мама).
  Порт-репликатор с COM-портом для Z505LE есть, адаптера к макбуку нет.
  До этапа 6 можно работать без него.
