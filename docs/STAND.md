# Стенд: управление ноутбуками с хоста

На каждом ноутбуке работает `w98agent.exe`, на макбуке — `tools/w98.py`
(нужен только Python 3). Агент слушает TCP 9898 и раз в три секунды шлёт
широковещательный маяк, по которому хост находит ноутбук по имени компьютера.

Авторизации у агента нет: любой в этой сети может выполнять на ноутбуке
команды. Сеть стенда должна быть изолированной (макбук и ноутбуки через
свитч, без выхода в интернет с этого интерфейса).

## Сеть

Настраивать адреса не нужно. Windows 98 и Windows на макбуке без DHCP сами
берут адреса из `169.254.x.x`; на это уходит около минуты после загрузки.
На макбуке надо один раз разрешить Python входящие UDP 9898 в брандмауэре.

## Установка агента на ноутбук (один раз, руками)

1. Скопировать `stand/agent/bin/w98agent.exe` в `C:\W98AGENT\`.
2. Запустить `C:\W98AGENT\w98agent.exe /install`.
3. Перезагрузить.

`/install` делает четыре вещи:

- прописывает агента в `RunServices` (стартует до входа пользователя);
- создаёт `C:\W98AGENT\W98BOOT.BAT`;
- вставляет его вызов первой строкой в `C:\AUTOEXEC.BAT` (копия прежнего
  файла — `C:\W98AGENT\AUTOEXEC.OLD`);
- в `C:\MSDOS.SYS` ставит `BootMenu=0`, `BootWarn=0`, `AutoScan=0`, чтобы
  после неудачной загрузки ноутбук не ждал у меню, а грузился обычным путём.

Позже эти же шаги уйдут в образ QuickInstall.

## Команды

```
python tools/w98.py discover                    кто в сети
python tools/w98.py -H z505 ping                состояние агента
python tools/w98.py -H z505 put  LOCAL REMOTE   файл на ноутбук
python tools/w98.py -H z505 get  REMOTE LOCAL   файл с ноутбука
python tools/w98.py -H z505 dir  "C:\WINDOWS\SYSTEM\ati*.*"
python tools/w98.py -H z505 exec "prog.exe args"    Win32-программа, скрыто, с выводом
python tools/w98.py -H z505 sh   "dir c:\"          команда через COMMAND.COM
python tools/w98.py -H z505 spawn "gta3.exe"        запустить на экране и не ждать
python tools/w98.py -H z505 shot desktop.png        снимок экрана
python tools/w98.py -H z505 reboot                  перезагрузка с ожиданием
python tools/w98.py -H z505 arm 120 / disarm        таймер «мёртвой руки»
python tools/w98.py -H z505 reset                   жёсткий сброс
```

`-H` принимает IP или начало имени компьютера. Вместо него можно задать
переменную окружения `W98_HOST`.

## Пробная установка драйвера с автооткатом

```
python tools/w98.py -H z505 snapshot
python tools/w98.py -H z505 trial build\atim1.drv=C:\WINDOWS\SYSTEM\atim1.drv ...
python tools/w98.py -H z505 confirm
```

1. `snapshot` перезагружает ноутбук, и `W98BOOT.BAT` ещё в DOS копирует
   `SYSTEM.DAT`, `USER.DAT`, `SYSTEM.INI`, `WIN.INI` в `C:\W98AGENT\GOOD`.
   Делается, когда система в заведомо рабочем состоянии.
2. `trial` кладёт файлы, ставит флаг `TRIAL.FLG` и перезагружает. При
   загрузке флаг превращается в `PENDING.FLG`.
3. Пока стоит `PENDING.FLG`, любая следующая загрузка возвращает реестр и
   ini-файлы из `GOOD` и ставит `ROLLED.FLG`.
4. `confirm` снимает `PENDING.FLG`: конфигурация остаётся.

Если Windows с пробным драйвером повисла при загрузке, нужно выключить и
включить ноутбук кнопкой; дальше он откатится сам.

Откат возвращает реестр и ini-файлы, но не удаляет скопированные файлы
драйвера: после отката на них просто ничто не ссылается.

## Таймер «мёртвой руки»

`arm N` — если за N секунд не пришёл `disarm`, агент перезагружает ноутбук:
сначала обычным способом, через 30 секунд — жёстким сбросом через порты
чипсета. Ставится перед рискованным тестом, который может повесить систему.

## Что проверено, а что нет

Проверено под wine на Linux: все сетевые команды, запуск программ с
таймаутом, снимок экрана, `/install` (реестр, `AUTOEXEC.BAT`, `MSDOS.SYS`,
генерация `W98BOOT.BAT`).

Не проверено, нужна настоящая Windows 98:

- запуск самого агента на Windows 98;
- работа `W98BOOT.BAT` в DOS (снимок и откат);
- жёсткий сброс через порты `0xCF9` и `0x64` на обоих ноутбуках;
- `sh`: перенаправление вывода `COMMAND.COM`.

## Сборка агента

Open Watcom 2: в `stand/agent` выполнить `wmake`. Готовый файл лежит в
`stand/agent/bin/w98agent.exe`.
